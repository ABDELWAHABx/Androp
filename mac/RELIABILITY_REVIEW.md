## BLE coverage and bandwidth

The [Bluetooth feature matrix](BLE_FEATURES.md) describes the actual command coverage and limits. Both peers need this version, one initial pairing and Bluetooth sync enabled. A usable network socket is preferred for throughput; supported small messages fall back to authenticated BLE.

This pass removes duplicate BLE media/volume commands, preserves seek/text parameters, starts status synchronization after BLE-only authentication and omits album-art encoding for BLE. Clipboard text is limited to 64 KiB UTF-8, with bounded acknowledgement retries. Notification/icon/photo payloads that exceed transport limits are rejected rather than filling an unbounded queue. The existing pairing-token protocol does not establish application-level encryption for BLE payloads.

File transfer, the file browser/WebDAV and the app's continuous remote trackpad require a reachable IP connection. USB support in the separate mirroring feature does not automatically provide a network connection for these features.

## Hotspot and Samsung Data Saver

The implementation uses normal app permissions and Android 16's public `TetheringManager` API. It does not add ADB, wireless-debugging, root, a privileged daemon or hidden-API policy changes for hotspot activation. The Android settings card and the existing dashboard notification provide user-tapped setup actions; remote commands do not force background activities open.

“Modify system settings” is a prerequisite for trying the supported fallback, not a promise of successful internet tethering. [Android 16's service permission checks](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/heads/android16-release/Tethering/src/com/android/networkstack/tethering/TetheringService.java#348) reject ordinary callers before the `WRITE_SETTINGS` fallback when the newer Soft AP configuration feature is enabled. Carrier provisioning can also fail. Native [start/stop callbacks](https://android.googlesource.com/platform/packages/modules/Connectivity/+/refs/heads/android16-release/Tethering/common/TetheringLib/src/android/net/TetheringManager.java#1392) report acceptance/failure; androp waits for actual tethered-interface state and ends observation after 20 seconds. Stopping may fail if the caller has no matching tethering request.

Global Data Saver changes require [MANAGE_NETWORK_POLICY in the system service](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/net/NetworkPolicyManagerService.java#3444), a [signature-only permission](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/core/res/AndroidManifest.xml#7242). An ordinary user permission cannot grant that ability. Exempting androp from Data Saver does not disable it globally. When it blocks activation, androp provides a Data Saver settings action and asks the user to retry after changing it. Samsung S21 FE/One UI 8 activation, cellular routing and BLE-only behavior remain physical-device checks.

## WebDAV security boundary

The Android WebDAV server now requires a random 256-bit capability token in its mount URL. The token is shared through the authenticated network session, kept in memory, revoked when that session ends or the app pauses, and regenerated as needed. Requests must remain inside the exported storage root; malformed paths and unsupported recursive directory depths fail. Finder mounts expose only `GET`, `HEAD`, `OPTIONS` and `PROPFIND`, with DAV class 1 rather than falsely advertising locking/writing.

**WebDAV file contents and its capability URL still travel over unencrypted HTTP.** A token prevents anonymous access without the token; it does not protect against someone able to observe that traffic. Use this mount only on a trusted local network. Finder or operating-system history may retain a mount URL; the app's revocation makes the old token unusable after session teardown. This change does not add WebDAV uploads or claim TLS protection.

## Verification status

Production-policy regressions were added for reconnect endpoints/generations, notification identity/actions/categories, clipboard outboxes, YouTube extraction, battery/dashboard/media publication, file staging/chunk bounds, WebDAV access, BLE control limits, app selection and floating-widget placement. The integrated Android debug/release build, unit tests and lint, native macOS builds/regressions, and packaged-app Pause/Resume checks are owned by the release workflow. Preview 3 passed **141 Android JVM tests**, debug and optimized release assembly, and lint with **0 errors, 252 warnings and 10 hints**. The independent [Android CI run](https://github.com/ABDELWAHABx/airsync-selfbuild/actions/runs/38087765759) is still running; the Android results above are from the completed local build and tests. [Native Mac CI](https://github.com/ABDELWAHABx/airsync-selfbuild/actions/runs/38087765717) passed the policy suite on macOS 15 and 26, compiled the app, verified signatures, and exercised three idle Pause/two Resume cycles. The [exact packaged app also passed on macOS 15.7.9](https://github.com/ABDELWAHABx/airsync-selfbuild/actions/runs/38088498273), with source and download hashes verified. The tests keep Bluetooth radio and the experimental power helper inactive; they do not establish physical-device interoperability.

Physical verification remains necessary for Samsung background behavior and Now Bar placement, BLE latency/interference, real battery use, hotspot permission/carrier behavior, multi-file performance and Mac sleep/lid behavior. The earlier [crash review](CRASH_REVIEW.md), [notification review](NOTIFICATION_REVIEW.md) and [closed-lid review](CLOSED_LID_REVIEW.md) retain their separate scope and limitations. No claim is made that every upstream issue or possible crash has been eliminated.
